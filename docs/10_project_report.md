# Project Report - Social Media Privacy Risk Assessment Framework

**Abstract.** This project builds a defensive, educational framework that estimates social-media privacy risk from self-reported settings and habits. A 44-question questionnaire is converted into ten category scores and a weighted 0-100 score (higher = more exposure) classified as LOW, MODERATE, HIGH or CRITICAL. The system produces findings, prioritised recommendations, an improvement simulation, a dashboard over 1,000 synthetic profiles and a printable report, while storing only minimal non-sensitive results.

**1. Introduction.** Social platforms mix personal sharing with identity, location and account-security risks. Users rarely see how these interact.

**2. Problem statement.** Existing privacy guidance is generic and often not measurable; tools that analyse "profiles" risk becoming surveillance tools themselves.

**3. Objectives.** Self-reported assessment; explainable scoring; prioritised guidance; privacy-by-design storage; synthetic analytics; automated testing.

**4. Social-media privacy background.** Audience controls, discoverability, tagging, apps and defaults determine exposure. Visibility is not automatically unsafe but widens what is reachable.

**5. Digital footprint.** Active footprint = deliberately shared; passive = generated by activity. Only self-reported practices are scored.

**6. Privacy vs security.** Privacy governs exposure and use of personal data; security protects access. A secure account can still expose too much (and vice versa).

**7. Social engineering.** Manipulation of trust; public context (employer, college, travel, family, interests, events) can make scams more believable. The project explains this defensively.

**8. Existing approaches.** Platform privacy checkups, generic checklists and awareness training. They seldom provide transparent weighted scoring or simulation of improvements.

**9. Proposed framework.** Questionnaire -> validation -> feature extraction -> category analysers -> scoring engine -> findings -> recommendations -> dashboard/report (`docs/03`).

**10. Questionnaire design.** 44 questions, 10 categories, choice-only answers, never asking for the sensitive value itself.

**11. Synthetic dataset.** 1,000 fictional profiles from a hidden "carelessness" variable with per-question base rates (seed 42). Result: mean 49.8, spread across all four levels. It supports the dashboard and is not claimed to represent real populations.

**12. Feature engineering.** `extract_privacy_features()` converts answers into risk values (risky 1, friends 0.4, sometimes 0.5, not sure 0.6, safe 0) and tracks protective controls.

**13. Category risk analysis.** Weighted average of question risks per category (question weights 1-3) scaled to 0-100.

**14. Risk scoring.** Overall = sum(category weight x category score); default weights 10/15/15/10/10/5/15/5/10/5 %; thresholds 20/40/70. Both are educational assumptions requiring validation.

**15. Findings engine.** A finding for each answer with risk >= 0.5, ranked by severity and weighted contribution.

**16. Recommendation engine.** Catalogue keyed by finding type with IMMEDIATE / IMPORTANT / GOOD PRACTICE priorities.

**17. Improvement simulator.** Re-scores modified answers; demo profile fell from 70 (HIGH) to 32 (MODERATE), a 38-point reduction. It is a simulation, not a safety guarantee.

**18. Account security.** MFA, unique passwords, manager, alerts, sessions, recovery info.

**19. Third-party applications.** Reviewing connected apps and applying least privilege.

**20. Location privacy.** Real-time sharing, geotags, check-ins, travel and routines; posting after leaving reduces immediate exposure versus live broadcast.

**21. Digital footprint analysis.** Old posts/accounts, public comments, periodic review.

**22. Privacy dashboard.** Six charts and summary cards (synthetic data).

**23. Privacy by design.** Data minimisation, purpose limitation, least privilege, default privacy, transparency, user control, retention limit, secure processing (`docs/04`).

**24. Testing.** 33 functional tests including boundary values 20/21, 40/41, 70/71.

**25. Security testing.** 12 tests: validation, XSS, rate limit, headers, deletion authorisation, retention, stateless sessions, safe errors.

**26. Results.** 45/45 tests pass. Synthetic distribution: LOW 180, MODERATE 263, HIGH 283, CRITICAL 274. Top weakness: old posts not reviewed (71%).

**27. Limitations.** Self-report bias; assumed weights; synthetic data; no platform-specific logic; simple limiter; no user accounts.

**28. Future scope.** Platform checklists, organisational policy configuration, awareness quizzes, maturity scoring, teen/family modules, enterprise training and GRC reporting, anonymous trend analysis, model calibration, localisation, accessibility, report comparison over time, local-only client mode. No invasive monitoring or scraping.

**29. Conclusion.** The framework shows that useful privacy assessment can be done with minimal data, transparent scoring and actionable advice, while remaining ethical and testable.
