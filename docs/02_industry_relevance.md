# Industry Relevance (Section 2)

| Area | How the project relates |
|---|---|
| Cybersecurity | Models exposure + account-security + social-engineering risk with a transparent scoring method. |
| Privacy engineering | Data minimisation, no PII collection, privacy-by-default storage design. |
| Security awareness | Findings are explained in plain language with prioritised actions and a printable checklist. |
| Enterprise security | The questionnaire/scoring model can be adapted to employee self-assessments (policy-configurable weights). |
| Digital-risk management | Likelihood/impact thinking, category scoring, risk matrix, simulation of control improvements. |
| Identity protection | Looks at attributes (birth date, contact details) and controls (MFA, recovery info) that affect impersonation risk. |
| Security consulting | Produces a client-style report: scores, top findings, priority actions, disclaimer. |
| Application security | Input validation, XSS-safe rendering, rate limiting, security headers, token-based deletion, tests. |
| GRC | Configurable weights/thresholds, documented assumptions, risk register style matrix, retention policy. |
| Employee training | Awareness content + dashboard of aggregate (anonymised) trends. |
